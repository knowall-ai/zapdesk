= ZapDesk Troubleshooting Guide
:toc: left
:icons: font

== Common Issues

[cols="2,3"]
|===
|Problem |Solution

|**"Sign in failed" after Microsoft login**
|Verify Azure AD redirect URI matches exactly: `https://zapdesk.yourdomain.com/api/auth/callback/azure-ad`. Check AZURE_AD_CLIENT_ID and AZURE_AD_CLIENT_SECRET are correct.

|**"Unauthorized" when viewing tickets**
|Session may have expired. Sign out and sign in again. Check NEXTAUTH_SECRET is set correctly and matches across deployments.

|**No tickets showing in list**
|Ensure work items have the "ticket" tag in Azure DevOps. Verify user has permission to access the Azure DevOps project. Check browser console for API errors.

|**"Failed to fetch tickets" error**
|Azure DevOps API may be down. Check https://status.dev.azure.com/. Verify AZURE_DEVOPS_ORG is set correctly. Check user has valid Azure DevOps license.

|**Comments not saving**
|User may not have write permission in Azure DevOps. Check the work item is not locked. Verify session hasn't expired.

|**Customers cannot see files attached to a reply**
|Files are emailed with a *public reply*, not with an internal note. A reply's files must fit in about 3 MB in total; any that do not are listed in the email as not included, and stay on the ticket.

|**Email webhook not creating tickets**
|Verify EMAIL_WEBHOOK_SECRET header matches. Check sender domain has project mapping. Review server logs for error details.

|**Blank page after login**
|Check browser console for JavaScript errors. Verify all environment variables are set. Clear browser cache and cookies.

|**"Invalid configuration" on login page**
|AZURE_AD_CLIENT_ID or AZURE_AD_TENANT_ID is missing or invalid. Check .env file and Azure App Service configuration.

|**Slow ticket loading**
|Large number of tickets may cause delays. Consider pagination. Check Azure DevOps API rate limits.

|**CSS/styles not loading**
|Clear browser cache. Run `npm run build` to regenerate styles. Check Tailwind configuration.

|**"Token expired" errors**
|Refresh token may have expired. Sign out and sign in again. Check token lifetimes in Azure AD app settings.

|**Can't see specific project's tickets**
|User lacks permission to that Azure DevOps project. Add user to project in Azure DevOps. Check project exists in organization.

|**Search not returning expected results**
|Search only covers client-side loaded tickets. Use Azure DevOps for advanced queries. Check filter settings.

|**Avatar images not loading**
|Azure DevOps image URLs may require authentication. This is expected behavior - initials shown instead.

|**"CORS error" in browser**
|API routes should proxy all requests. Check you're using /api/ routes, not calling DevOps directly. Verify NEXTAUTH_URL is correct.

|**Deployment failing**
|Check GitHub Actions logs. Verify AZURE_CREDENTIALS secret contains valid service principal. Ensure Node.js version matches (20+).

|**503 Service Unavailable / Exit code 127 after deployment**
|Exit code 127 means "command not found". This usually means node_modules are missing. The app requires `output: 'standalone'` in `next.config.ts` for Azure App Service. The standalone build creates a self-contained package in `.next/standalone/` with all dependencies bundled. Deploy this folder and use `node server.js` as startup command instead of `npm start`.

|**.next folder not deployed**
|Ensure `include-hidden-files: true` is set in the upload-artifact action. Files/folders starting with `.` are excluded by default.

|**"Publish profile is invalid" deployment error**
|SCM Basic Authentication may be disabled. Check with: `az rest --method get --url "https://management.azure.com/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.Web/sites/{app}/basicPublishingCredentialsPolicies/scm?api-version=2022-03-01" --query "properties.allow"`. If false, switch to service principal authentication using azure/login action.

|**Custom domain not working**
|Verify DNS CNAME record. Check Azure SSL certificate status. Allow up to 24 hours for DNS propagation.

|**HTTP ERROR 431 ("This page isn't working") on localhost, usually right after signing in**
|"Request Header Fields Too Large" — the `Cookie` header exceeded Node's 16 KB `maxHeaderSize`. All localhost ports share one cookie jar, so cookies from every other dev app you've run accumulate on `localhost`, and the NextAuth session cookie is itself large because it carries the Azure AD access, refresh and id tokens (chunked as `next-auth.session-token.0`, `.1`, …). Fix either side: clear cookies for `localhost` (Chrome: DevTools → Application → Cookies → `http://localhost:3102` → Clear all, or visit `chrome://settings/content/all?searchSubpage=localhost`), or start the server with a bigger limit — `NODE_OPTIONS=--max-http-header-size=65536 bunx next dev --port 3102`. Confirm which it is with `curl -s -o /dev/null -w "%{http_code}" http://localhost:3102/` — a plain curl sends no cookies, so it returns 200 while the browser gets 431.

|**Sign-in redirect fails / lands back on the login page in local dev**
|`NEXTAUTH_URL` must match the port the dev server actually binds. `bun run dev` binds **3102** (see `package.json`), and `.env.example` agrees — but an `.env` copied before that, or an Azure AD app registration still listing a 3000 callback, will bounce you back to the login page. The redirect URI has to match too: `http://localhost:3102/api/auth/callback/azure-ad`. A mismatch shows up as `AADSTS50011`.

|**A card dragged on the Kanban board goes back to its old column**
|If a message appears, it gives the reason Azure DevOps refused the move, usually a workflow rule on that work item type. A column that turns grey while you drag is one the card's type has no state for (hover it for the reason). With no message at all on a version before the fix for issue #366, a board refresh arrived during the drag: drop the card again, or turn *Live update* off while moving several cards.

|**The Kanban board's 24h summary shows "PRs: unavailable", or more than 24 hours on a Monday**
|The summary covers the last 24 _working_ hours: weekend time doesn't count, so on a Monday it reaches back to the same time on Friday (the label then reads *Since Fri 10:23*). Bank holidays still count as working days. "Unavailable" means the pull request lookup failed. The server log shows `Failed to fetch pull request activity` with the project and the Azure DevOps response. The signed-in user needs *Code (Read)* access to the project's repositories. Pull requests come from Azure DevOps only, so with the header toggle on *GitHub* the PR counts stay at zero.

|**The 24h summary counts merged pull requests but *Highlight* lights up no cards for them**
|A card is highlighted for a pull request only when the pull request is linked to the work item (the *Work items* panel on the pull request in Azure DevOps), and the work item is on that group's board. Under *Person* grouping, a pull request is counted for its author, and its linked items may be assigned to someone else.

|**The Both / DevOps / GitHub toggle is missing from the header**
|GitHub issues are not configured. Either set up the ZapDesk GitHub App (`GITHUB_APP_ID`, `GITHUB_APP_SLUG`, `GITHUB_APP_CLIENT_ID`, `GITHUB_APP_CLIENT_SECRET` and `GITHUB_APP_PRIVATE_KEY`), or set both `GITHUB_TOKEN` and `GITHUB_PROJECT_REPOS`, in the App Service configuration and restart. Check the server log for `[GitHub] GITHUB_PROJECT_REPOS` warnings: the value must be a JSON object such as `{"Project": ["owner/repo"]}`.

|**The toggle is there but no GitHub issues are listed**
|With the ZapDesk GitHub App, the project must be connected: its project page shows the GitHub organisation, and *Choose repositories on GitHub* lists the repositories the App may read. With `GITHUB_PROJECT_REPOS`, the project name must match an Azure DevOps project in the selected organization that you can see (case does not matter). Only open issues and closed issues updated in the last seven days are listed.

|**The same person is listed twice, under their name and under a GitHub username**
|The GitHub account is not linked to the person. They can save their GitHub username in the *GitHub* card on their *Profile* page. For someone outside the tenant, add the username to `GITHUB_USER_MAP` in the App Service configuration instead, as `{"github-username": "DevOps Display Name"}`, and restart; the name must be the person's display name in Azure DevOps. Check the server log for `[GitHub] GITHUB_USER_MAP` warnings.

|**A GitHub username saved on the profile has no effect**
|Another server may still have the old list: allow up to ten minutes. If it never applies, the server log shows `[GitHub] Could not read the GitHub usernames saved on profiles`: the app registration needs the Microsoft Graph application permission `User.ReadWrite.All` with admin consent. A person is matched to an Azure DevOps user by email address, then by display name.

|**"GitHub username … is already linked to another person"**
|Someone else saved that username on their profile. If it is wrongly theirs, they can remove it from their *Profile* page; an admin can override it with a `GITHUB_USER_MAP` entry.

|**"Could not check whether this GitHub username is already linked"**
|Before saving, ZapDesk reads every user in the tenant to make sure no one else has linked the username, and refuses the save if it cannot. The server log has the reason: a Graph error means the app registration lacks the Microsoft Graph application permission `User.ReadWrite.All` (with admin consent); `IncompleteUserListError` means the tenant has more than 5,000 users, more than the check reads. Use `GITHUB_USER_MAP` for that person instead.

|**/install says "This ZapDesk serves one organisation"**
|`AZURE_AD_MULTI_TENANT` is not `true`, or `AZURE_AD_CLIENT_ID` is not set. Set both in the App Service configuration and restart; the app registration must also be multi-tenant.

|**/install says "ZapDesk could not be installed" with `AADSTS50011`**
|The callback is not a redirect URI of the app registration. Add `https://<your ZapDesk URL>/api/install/callback` as a *Web* redirect URI.

|**/install says "That install link has expired"**
|The admin took more than ten minutes on Microsoft's page, or finished in another browser. Start again from `/install` in the same browser.

|**Someone from another organisation gets `AADSTS50020` or `AADSTS700016` at sign-in**
|The app registration is still single-tenant. Set *Supported account types* to multitenant. Their admin must also have installed ZapDesk from `/install`.

|**"No Azure DevOps organization selected. Choose one, or set AZURE_DEVOPS_ORG."**
|ZapDesk has no built-in organization. Pick one in the organization selector in the header. For server-side work that has no user (email ingest, routing and SLA lookups), set `AZURE_DEVOPS_ORG` in the App Service configuration and restart.

|**Mail from a customer's domain is not routed to their project**
|Add an `Email: example.com` line to the project's description in Azure DevOps. There are no built-in domains. The routing map refreshes every five minutes, and needs both `AZURE_DEVOPS_PAT` and `AZURE_DEVOPS_ORG`.

|**No GitHub card on the project page**
|The ZapDesk GitHub App is not set up on this server. Set `GITHUB_APP_ID`, `GITHUB_APP_SLUG`, `GITHUB_APP_CLIENT_ID`, `GITHUB_APP_CLIENT_SECRET` and `GITHUB_APP_PRIVATE_KEY`, and restart.

|**The project page says "Someone who can edit this project … can connect GitHub"**
|Only people with *Edit project-level information* on the project in Azure DevOps (Project Administrators, by default) can connect or disconnect GitHub.

|**After installing the App: "GitHub was not connected: you need to be able to edit this project …"**
|Either Azure DevOps refused the change (you cannot edit the project), or the GitHub user who authorised the App cannot see that installation. The server log says which. The App must have *Request user authorization (OAuth) during installation* ticked.

|**After installing the App: "That GitHub link has expired"**
|The link is valid for 30 minutes and only for the person who clicked *Connect GitHub*. Click it again.

|**The project is connected but no GitHub issues show**
|Check the App was given the repositories on GitHub (*Choose repositories on GitHub* on the project page). Changes to the repository list take up to five minutes to show.

|**The GitHub card is missing from the Profile page**
|It appears only when GitHub issues are configured (`GITHUB_TOKEN` and `GITHUB_PROJECT_REPOS`).

|**"Could not load GitHub issues from owner/repo"** (or **from owner/***)
|For `owner/*`: the owner must be a GitHub organization, not a personal account, and the token must be allowed to read it. Otherwise: the token cannot read that repository. Check the repository name, that the token has read-only *Issues* access to it, and that it has not expired. The server log has the status GitHub returned: 404 means not found or no access, 401 an invalid token, 403 or 429 the rate limit.
|===

== Debugging Tips

=== Check Server Logs

In Azure App Service:
[source,bash]
----
az webapp log tail --name zapdesk-knowall --resource-group KnowAllAIRG
----

Or download logs:
[source,bash]
----
az webapp log download --name zapdesk-knowall --resource-group KnowAllAIRG --log-file logs.zip
----

=== Check Browser Console

1. Open browser developer tools (F12)
2. Go to Console tab
3. Look for red error messages
4. Check Network tab for failed requests

=== Verify Environment Variables

[source,bash]
----
# Local development
cat .env

# Azure App Service
az webapp config appsettings list --name zapdesk-knowall --resource-group KnowAllAIRG
----

=== Test Azure DevOps Connection

[source,bash]
----
# Test API with PAT
curl -u ":YOUR_PAT" "https://dev.azure.com/KnowAll/_apis/projects?api-version=7.0"
----
